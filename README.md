# 지하철 혼잡도 예측 모델 개발

본 리포지토리는 서울교통공사의 '승하차 인원 데이터'를 기반으로 '지하철 혼잡도'를 예측하는 머신러닝 프로젝트입니다.

이 프로젝트는 **초기 가설의 실패**와 **데이터의 실제 의미에 대한 재파악**을 거쳐, 최종적으로 7호선에 대한 고성능 XGBoost 예측 모델을 개발하는 전 과정을 담고 있습니다.

---

## 1부: 초기 가설 및 실패 (3호선 선형 모델)

### 🎯 초기 가설
[cite_start]프로젝트의 초기 목표는 "승하차 인원의 변화량($X$)"과 "혼잡도의 변화량($Y$)" 사이에 $Y = \alpha X$ 라는 **단순 선형 관계**가 존재할 것이라 가정했습니다[cite: 74, 76, 77].

* $X$ = (분기별 승하차 인원) - (연평균 승하차 인원)
* $Y$ = (분기별 혼잡도) - (연간 혼잡도)

### 🛠️ 워크플로우 (초기 모델 Steps 1-4)
1.  [cite_start]**[Step 1] 혼잡도 데이터 전처리:** 2024년 3호선의 분기별/연간 `혼잡도` 데이터를 로드하여, '연평균 대비 분기별 혼잡도 변화량'($Y$)을 계산했습니다[cite: 60, 61, 74].
2.  [cite_start]**[Step 2] 승하차 데이터 전처리:** 2024년 3호선 `승하차 인원` 데이터를 로드하여 전처리했습니다[cite: 47, 58].
3.  [cite_start]**[Step 3] 승하차 흐름 데이터 생성:** '승차량'에서 '하차량'을 빼고, '연평균 대비 분기별 순수 유입량'($X$)을 계산했습니다[cite: 75].
4.  [cite_start]**[Step 4] 최소제곱법(OLS) 적용:** $X$와 $Y$의 관계를 가장 잘 설명하는 계수($\alpha$)를 `최소제곱법`으로 추정했습니다[cite: 77, 82].

### 📉 결과: 가설 실패
* [cite_start]예상과 달리 **$R^2$ (결정계수) 값이 -0.33 ~ -4.12**로 극도로 낮거나 음수로 나타났습니다[cite: 84, 89, 92, 95].
* [cite_start]**결론:** '승하차 인원 변화'와 '혼잡도 변화' 사이의 **선형 관계 가정이 완전히 틀렸음**을 확인했습니다[cite: 96, 97].

## 🔍 핵심 발견: 데이터의 실제 의미 파악

[cite_start]가설 실패의 원인을 찾기 위해, 데이터 제공처인 **서울교통공사에 직접 문의**했습니다 [cite: 99-103].

* **기존 가정:** '2023년 혼잡도 데이터' = 2023년 **전체 1년치**의 평균일 것이다.
* [cite_start]**실제 답변:** 공사에서 제공하는 '연간 데이터'는 **해당 연도의 특정 1주일(예: 2023.11.06 ~ 2023.11.12) 동안의 평균값**이었습니다 [cite: 108, 111-115, 126, 130, 132].

이 발견으로 인해, 연평균과 분기별 데이터를 비교하려던 **초기 가설(1부) 전체가 무효화**되었습니다.

## 2부: 본 예측 모델 개발 (7호선 ML 모델)

### 🎯 새로운 전략 (수정된 모델)
[cite_start]데이터의 실제 의미(특정 기간의 평균값)를 파악한 후, 프로젝트의 목표를 **"특정 기간의 승하차 인원($X$)으로 동일 기간의 혼잡도($Y$)를 예측"**하는 표준 머신러닝 회귀 문제로 전면 수정했습니다 [cite: 138-144].

### 🛠️ 워크플로우 (수정된 모델 Steps 1-5)
1.  **[Step 1] 혼잡도 데이터 전처리:**
    * 2022년, 2023년, 2024년 7호선 `열차혼잡도` 데이터를 로드합니다.
    * [cite_start]30분 단위 데이터를 1시간 단위(`06 ~ 07` 등)로 평균내어 집계합니다 [cite: 147-149].
2.  **[Step 2] 승하차 인원 데이터 전처리:**
    * [cite_start]2022년, 2023년, 2024년 7호선 `승하차인원` 데이터를 로드합니다[cite: 153].
    * [cite_start]일별 데이터를 `요일구분`(평일/토/공휴일) 기준으로 평균을 내어 집계합니다[cite: 155].
3.  **[Step 3] 피처 엔지니어링 (시간 인코딩):**
    * 모델 성능 비교를 위해, '시간' 피처를 3가지 방식으로 인코딩하여 3종류의 데이터셋을 생성합니다.
        * [cite_start]**One-Hot Encoding** (피처 수 증가, 시계열성 무시) [cite: 158-162]
        * [cite_start]**Label Encoding** (시계열 순서 반영, 선형성 문제) [cite: 164-170]
        * [cite_start]**Cyclic Encoding** (Sine/Cosine 변환, 주기성 반영) [cite: 172-175]
4.  **[Step 4] 데이터 병합:**
    * `혼잡도`(y)와 `승하차 인원`(X) 데이터를 `연도` 및 `인코딩 방식`별로 병합하여, `total_22_cyclic.csv` 등 최종 데이터셋을 생성합니다.
5.  **[Step 5] 모델 학습 및 튜닝:**
    * **데이터 분할:** `2022년` (Train) / `2023년` (Validation) / `2024년` (Test) 데이터로 시계열 분할합니다.
    * [cite_start]**모델 비교:** `LinearRegression`, `Ridge`, `XGBRegressor` 모델의 성능을 비교합니다[cite: 177, 184].
    * [cite_start]**튜닝:** `GridSearchCV` 등을 사용하여 `Ridge`와 `XGBoost`의 하이퍼파라미터를 최적화합니다 [cite: 187, 194-195].

### 📊 결과 및 추가 검증
* [cite_start]**모델 성능:** `XGBoost` 모델이 `LinearRegression`이나 `Ridge`에 비해 압도적으로 높은 성능(R²)을 보였습니다[cite: 178, 184].
* [cite_start]**인코딩 성능:** `Cyclic Encoding`(주기 인코딩)을 사용한 `XGBoost`가 하이퍼파라미터 튜닝 후 **Test $R^2$ 0.973**으로 가장 높은 성능을 기록했습니다[cite: 190, 196].
* [cite_start]**추가 검증:** 최종 튜닝된 모델을 학습/테스트에 사용하지 않은 **2024년 3월, 6월, 9월 데이터**로 추가 검증한 결과, 여전히 **$R^2$ 0.96~0.97**의 안정적인 성능을 보여 모델의 일반화 가능성을 확인했습니다 [cite: 197-200].

## 🏁 결론 및 향후 과제
* [cite_start]'승하차 인원'($X$)으로 '혼잡도'($Y$)를 예측하는 **고성능 XGBoost 회귀 모델을 성공적으로 구축**했습니다[cite: 202].
* [cite_start]현재 모델은 7호선에 국한되어 있으므로, **타 노선으로의 일반화 가능성**을 검토할 필요가 있습니다[cite: 203].
* [cite_start]최종 목표인 "미래 혼잡도 예측"을 위해서는, "과거 승하차 데이터 $\rightarrow$ **미래 승하차 예측 모델**"을 먼저 구현한 뒤, 이 두 모델을 연결하는 작업이 향후 과제로 남아있습니다[cite: 204, 205].
